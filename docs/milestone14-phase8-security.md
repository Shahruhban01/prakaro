# Phase 8 security

Policy mutations validate tenant and role on the server. Super Admin has platform scope, and Admin and Moderation Admin manage their organization. In this phase both draft and publication capabilities map to these existing roles. The system does not create a separate privilege domain. Supervisors see permitted clarification work through organization, active LOB grants and existing team scope. An ordinary moderator can view subscribed policy guidance and their own clarification thread. QA auditors read original policies through an authorized QA review.

The version ID in the submission must match the reservation. Verification uses existing independent evidence authorization. Published documents have bounded declarative schemas, no executable scripting or HTML rendering. Clarification messages are shown as text. The workspace returns only the reporter category and notes from report metadata, with other reporter identifiers omitted.

Policy changes and clarification mutations append scoped events to the existing audit table. Clarification content stays in the restricted transcript, referenced by message ID in audit. Historical decision and clarification foreign keys prevent orphaned versions. Published policy content remains unchanged if a subsequent assignment or version changes.
