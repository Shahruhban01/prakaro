# Phase 7 correction and publication

A finalized failure can lead to a versioned correction. Recommendation accepts Approve with current independently supported evidence, Reject, or Escalate. Recommendation and QA assessment do not change public verification. The original moderator and original auditor cannot commit the correction.

A supervisor must start a correction lease. Commit locks the review and case and verifies an unchanged revision and effective decision. The existing publication service revalidates evidence before making a confirmed claim. Where the original verified claim is withdrawn, the service appends a needs-evidence label only if the original publication can be identified and is still current. Earlier or superseding verification remains protected.

Commit appends a new decision version and keeps the original inputs and QA result. The old decision is marked superseded. The publication label, timing and approving reviewer are recorded on the correction and in its audit trail. The existing moderator foreign key is retained on the new version; for a platform operator the original staff ID fills that required column and the authoritative correction actor is in the correction and audit event. Corrections are excluded from ordinary sampling and AHT.

Historic approvals without canonical publication provenance require investigation through the existing authorized verification workflow. The supervised correction workspace issues a replacement version directly. It does not send a case back to the random allocator.
